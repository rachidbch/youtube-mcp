# Version 1 compatibility contract

This document records the public MCP contract established by
`@granitebps/youtube-mcp` 1.0.0. Patch and minor releases in the 1.x line
preserve this contract. A breaking change belongs in a new major release and
must be explicitly documented.

## Runtime and transport

- The server runs over standard input/output (`stdio`) by default, and over
  Streamable HTTP with `--http` or `TRANSPORT=http`.
- The executable is `youtube-mcp` from the `@granitebps/youtube-mcp` npm
  package.
- Node.js 22 or newer is the declared supported runtime.
- No YouTube API key or account is used.

## Tools

All tools are read-only and access an open-world service. A `video` input
accepts an 11-character video ID or a `youtube.com` / `m.youtube.com` /
`music.youtube.com` / `youtube-nocookie.com` / `youtu.be` URL in watch, short
link, embed, `v`, shorts, or live form.

| Tool                       | Input                                                                                                                                                     | Structured result                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `get_video_info`           | `video`                                                                                                                                                   | Video metadata                            |
| `get_transcript_languages` | `video`                                                                                                                                                   | `available` plus the caption track list   |
| `get_video_transcript`     | `video`; optional `lang` (2–10 characters); integer `maxSegments` ≥ 0, default 0; integer `startSegment` ≥ 0, default 0                                    | One page of one caption track             |
| `get_video_comments`       | `video`; `maxResults` 1–20, default 20; `sortBy` `relevance` or `time`; `page` ≥ 1, default 1                                                              | One page of comment threads               |
| `search_youtube`           | non-empty `query`; `maxResults` 1–50, default 10; `sortBy` `relevance`, `date`, `viewCount`, or `rating`; `uploadDate`; `videoDuration`                    | Search results                            |

## Result shapes

`get_video_info` returns `videoId` and `title` as strings, `tags` as a string
array, and nullable `description`, `channelName`, `channelId`, `uploadedAt`,
`duration`, `durationSeconds` (positive integer), `viewCount`, `likeCount`,
`commentCount`, and `thumbnailUrl`. `null` means YouTube did not provide the
value. `videoId` always equals the requested ID.

`get_transcript_languages` returns `videoId`, `available`, `totalTracks`,
`manualCount`, `autoGeneratedCount`, and `languages` (each with `languageCode`,
`languageName`, and `isAutoGenerated`) in YouTube's order. `available: false`
means the video is playable and has no caption tracks.

`get_video_transcript` returns `videoId`, nullable `languageCode`, `available`,
`totalSegments`, `startSegment`, `returnedSegments`, `hasMore`, nullable
`nextStartSegment`, `plainText`, and `segments` (each with `index`,
`offsetSeconds`, nullable `durationSeconds`, `timestamp`, and `text`).
`isAutoGenerated` is optional and nullable. When `available` is false, `reason`
is `NO_CAPTIONS` or `LANGUAGE_UNAVAILABLE`, and `availableLanguages` lists the
existing codes for the latter. Without `lang`, the first manual track is
returned, or the first auto-generated track when there is no manual one.
`maxSegments` 0 returns up to the server's per-response cap.

`get_video_comments` returns `videoId`, `page`, `sortBy`, `totalFetched`,
`threadCount`, `hasMore`, and `threads`. `search_youtube` returns `query`,
`resultCount`, the requested filters, `results`, and an optional `warnings`
array (each with `code` and `message`) for options YouTube search cannot apply
exactly.

Successful calls provide MCP structured content plus a short human-readable
text summary. Agents should read structured content.

## Errors

Tool failures set `isError: true`. The text begins with `❌ [CODE]`, and
`_meta["youtube-mcp/error"]` contains:

```json
{
  "code": "ERROR_CODE",
  "message": "readable message",
  "retryable": false,
  "upstream": {}
}
```

`upstream` may contain `httpStatus`, `url` (host and path only),
`playabilityStatus`, `reason`, `accessKind`, and `availableLanguages`. The
stable error codes are `INVALID_INPUT`, `ACCESS_BLOCKED`, `VIDEO_UNAVAILABLE`,
`COMMENTS_UNAVAILABLE`, `PARSE_ERROR`, `LIMIT_EXCEEDED`, `TIMEOUT`, `CANCELLED`,
and `UPSTREAM_ERROR`. `accessKind` is `rate_limited`, `forbidden`,
`login_required`, or `consent_required`. An access failure is never reported as
a missing video or missing captions.

## Configuration

The environment variables `YT_INIT_TIMEOUT_MS`, `YT_REQUEST_TIMEOUT_MS`,
`YT_TRANSCRIPT_MAX_BYTES`, `YT_TRANSCRIPT_MAX_SEGMENTS`, and
`YT_TRANSCRIPT_PAGE_MAX_SEGMENTS` accept positive integers. Invalid values stop
the server at startup. Defaults may change in minor releases.

## Compatible changes within 1.x

The following changes are compatible when existing behavior remains intact:

- adding optional result fields or `upstream` details;
- adding an error code for a failure that previously had `UPSTREAM_ERROR`;
- improving parsing, classification, diagnostics, or documentation;
- accepting additional YouTube URL forms;
- adding a new tool without renaming or changing an existing tool.

The following require a new major version:

- removing or renaming a tool, input field, result field, or error code;
- making an optional input or result field required;
- narrowing accepted input ranges or formats;
- moving the error object out of `_meta["youtube-mcp/error"]`;
- changing the package name, executable name, or `stdio` default transport;
- changing an existing field's type or established meaning.

YouTube availability, rate limiting, caption availability, and response layout
are operational behavior rather than guarantees of this contract.
